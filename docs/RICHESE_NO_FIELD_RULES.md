## Verified lifecycle

Richese has three tokens numbered 0,3,5. A shipment may use a concealed token at the one-force price. Until reveal it counts as one force, including zero, and moves like a force. At most one may be on the planet. Successive own/allied uses cannot repeat the same token. Revealed tokens stay faceup until another is placed. Voluntary reveal is permitted before Battle; battle reveal occurs with the Battle Plan. Revelation materializes the indicated reserves, capped by reserves available. Storm/worm exposure reveals and loses the indicated forces. Allied shipment immediately reveals; an existing token must first be revealed. Atreides cannot inspect the token battle's dial, and zero still plays a leader/cards. Gamont forces reveal and returns one force if present. The marker collects as one force. Heighliner activates except when shipping Guild as ally. Allied cost is one in a stronghold, two elsewhere; either ally may pay Guild/bank. Smuggler can add one in an empty territory. Karama prevents the No-Field shipment. Richese also blocks Fremen's Tuek victory condition. [R2 pp.5–6,10–12](https://www.gf9games.com/dune/wp-content/uploads/2021/11/CHOAM-Rulebook-low-res.pdf)

Terror can trigger when a No-Field enters, including zero. Materializing an already-present token does not trigger Terror again. [R3 p.14](https://www.gf9games.com/dune/wp-content/uploads/EcazMoritani-Rulebook-LOWRES.pdf)

## Pure model contract

The isolated module owns three physical token identities, their private values, the single deployed marker, and the most recently shipped token identity. It does not own player force arrays, reserves, Tanks, payment, turn order, card effects, reaction windows, movement allowance, or engine authorization.

History must be separate from board custody. Revealing or destroying a marker returns the same physical component to the faceup used position; it does not reset which token was last shipped. An allied immediate reveal updates the same history. Placing another token releases the previous faceup token for a later use. Turn changes do not make the last token reusable by themselves.

The engine supplies stable distinct token IDs and legal map locations. Public projection exposes a single concealed board presence and, when no token is deployed, the last faceup value. It never exposes the deployed token ID, ordered supply identities or other remaining values: those can reveal the concealed denomination by correlation or elimination. The owner receives the full token model. Force reserves must not be decremented on concealed placement merely to display a token; materialization is the later physical transfer.

A reveal returns the token's value, controller, exact location and reserve-limited materialized quantity. The caller then applies the appropriate physical outcome. This is deliberately different from the public effective count of one. A zero token returns zero materialized forces and still returns its used component/history normally. An allied shipment is a deploy-plus-reveal transition; it cannot leave a second hidden marker or silently forget the first.

The module uses an exact territory/sector location so the engine can distinguish the marker's exposed sector from sheltered forces elsewhere in a multi-sector territory. Location validation here checks structure only; the board engine must supply map membership, occupancy, path and shelter legality.

## Unresolved or compositional boundaries

1. **Reserve shortage when destroyed.** Voluntary/battle text explicitly caps by reserves; the destruction sentence says to lose the indicated quantity without repeating the shortage clause. The pure model caps materialization to avoid creating physical units, but that is conservation-based composition for storm/worm losses, not an independently answered FAQ. It does not select substitute losses from unrelated board forces.
2. **Mixed forces and battle dials.** The FAQ forbids dialing more than reserves in a No-Field battle. Existing ordinary counters are possible, but no retrieved specific answer defines the cap across those counters, multiple sectors, typed units or independent reserve uses. Basic/Advanced ordinary and the selected Advanced Occupy prototype use the explicitly provisional additive pool above. This does not settle that source question or admit Basic mixed coalition/module profiles.
3. **Full-plan special Karama and structured Truthtrance.** The current prototype distinguishes supplied p27 F's special entire-plan power from p27 C/p36 B ordinary Prescience under the explicit provisional contract above; private reading does not reveal the physical token. No retrieved dedicated combined FAQ adjudicates that distinction or broader promise questions. Structured Truthtrance, public maxima, other-player legal previews and reasoning retain their original entitled boundaries.
4. **Homeworld use.** R3 recommends Richese in a Homeworld combination but supplies no retrieved No-Field-specific rule defining off-planet hidden custody, one-on-planet versus off-planet coexistence, or homeworld threshold disclosure. General module availability is not an answer to those lifecycle questions. The isolated model represents a single Arrakis marker and does not authorize Homeworld placement.
5. **Capturing, transferring or returning a concealed marker as a force.** Movement-as-a-force and Gamont's explicit forced reveal do not establish a general conversion for every card or Guild transport-to-reserves. A generic return helper must not erase a hidden token without a source-backed reveal/custody cause. This module exposes no such automatic escape from last-use history.
6. **Allied discounts and reserve source.** Ordinary consent, typed allocation and funding are integrated. Guild-recipient and already-active Karama price/payee use the explicitly provisional prototype in both modes. Ordinary Fremen reserves are on-planet and remain ineligible for this off-planet method. See `RICHESE_ALLIED_SHIPMENT_AUDIT.md`.
7. **Supply orientation.** Concealed denomination is explicit. Hiding unused IDs/values in public JSON is the minimum privacy consequence, not a claim about an otherwise undocumented physical supply layout. The last revealed used face is public until another deployment; historical log knowledge may legitimately remain.
