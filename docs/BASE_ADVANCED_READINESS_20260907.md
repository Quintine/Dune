# Six-base-faction Advanced readiness audit

Read-only runtime audit, 7 September 2026. Scope is classic GF9 Advanced with any valid selection of the six original factions, two through six players, **no expansion and no optional module**. This document does not enable a mode or certify complete rules compliance. It reads the full active goal and preserves its wider twelve-faction scope.

## Finding

The unconditional Advanced start gate in `game/engine.ts:1500` remains justified by **base-only** missing rules and unresolved behavior. Expansion work is not the only reason for that gate. Most distinct Advanced faction mechanisms already have substantial engine, controls and focused-test support; rebuilding them would waste useful work. The next work should close the named base gaps below, independently review the existing mechanisms, and then run authentic Advanced setup and full games before enabling the mode.

Runtime was frozen for a separate calibration during this audit. No runtime, test, package, live room, server, automation or gate was changed. Line references describe the files inspected at this checkpoint and can move after integration.

## Explicit unresolved base interpretations

These are actual recorded implementation choices, not missing expansion components. Resolve from authoritative sources where possible; do not silently turn the current tests into the rulebook.

1. **Unfunded auction recovery after losing Karama.** `recoverAuctionPayment` at `game/engine.ts:2894–2917` explicitly labels its recovery provisional. It restarts the same lot when no spice or usable Karama can back the winning bid. In Advanced this is reachable when Harkonnen's special exchange removes the only funding Karama, or a BG Worthless conversion is canceled. `tests/special-karama.test.ts:223` and `tests/bg-karama.test.ts:285` verify that software policy, including the provisional restart; they do not establish publisher authority for it. `game/reference.ts:1924` keeps the limitation visible. Audit what happens to the standing bid, turn, card custody and any explicit ally contribution before certifying this path.
2. **Guild special shipment-stop settlement.** `game/reference.ts:1925–1926` says stopped shipment consumes the ordinary shipment opportunity while preserving forces, spice, allied credit and any rate card, then explicitly calls these settlement details provisional. The separate ordinary Guild-rate audit notes that the brief publisher power does not settle all changed-price/refund/order cases. Existing focused stop tests show safe rollback and resumption of this implementation; they do not resolve the rule interpretation. Keep ordinary permission/rate cancellation distinct from this once-per-game special stop.
3. **Atreides special full-plan commitment order.** `prepareSpecialKaramaIntent` at `game/engine.ts:7325` requires a pre-plan `fullPlanOffer`, after ordinary preparation, then forces the target to commit first. `game/reference.ts:1920` explicitly identifies this as an implementation timing choice needing the remaining card-interaction audit. It is not evidence that full-plan prescience itself is absent. Verify Base Truthtrance, Voice, Ghola/preparation and ordinary prescience interruptions against publisher sequencing, then document the supported order and exceptions. The expansion No-Field full-plan guard at `:7348` is irrelevant to this base-only configuration.

The broad Truthtrance language creates an engineering and guidance gap even if some natural-language enforcement requires a later user interpretation. It should not be disguised as an ambiguity that excuses all knowable structured questions.

## Missing mode-level evidence and stale guidance

`tests/bots.test.ts:160` is explicitly a test of implemented Advanced **subsystems**. It starts a Basic table at `:167`, completes Basic setup, flips `g.advanced = true` at `:188`, and injects elite reserves. It runs Hard and Brutal only. It is useful regression evidence but skips real Advanced setup, starting advisors/Fedaykin placement and Easy/Medium Advanced play. The final current checkpoint in `docs/IMPLEMENTATION_STATUS.md:28–45` records 1,418 registered rules/client/component tests, 113 persisted/API tests, TypeScript/lint/build and 312 Basic games with zero rejected candidates. The two 96-game studies and the two-through-six-player 120-game study are still Basic only; their successful results cannot certify Advanced. The earlier single worm-ride rejection is preserved as historical evidence in `docs/AI_PLAYER_COUNTS_20260907.md`, followed by its successful final rerun.

Before enabling the base Advanced gate, introduce an internal testable supported setup path that exercises the same initializer as production without weakening the public gate. Run the full matrix of player counts, relevant base-faction rosters and all four AI profiles, including all-human waiting, mixed ownership and alliances. Record every rejected candidate, stalls and complete traces with stable source fingerprints. Ensure targeted interactions actually occur; random completed games alone may never invoke a held special Karama or captive.

Browser evidence in `docs/VISUAL_PLAYTEST.md` explicitly distinguishes isolated Advanced/expansion fixtures from complete games. It does not demonstrate a complete Advanced base game from lobby through outcome. Required next acceptance includes actual Advanced setup, sealed spice support and elite casualty choices, KH inspection, captive ownership/execution, advisor conversion and Guild out-of-order actions, two spice piles and private forecast. Test refresh and server restart with representative pending private choices. Desktop and mobile must both show usable controls and correct waiting ownership.

`app/rules/coverage/page.tsx:29–72` has stale coarse rows for Advanced setup/advisors, first-storm orientation and some already implemented powers; its expansion and portrait rows are also outdated. `game/reference.ts` has much more precise boundaries but remains a partial reference. Consolidate coverage into one traceable source with separate implementation, player-control, AI, documentation and verification states per rule. Updating the stale rows is useful maintenance, but does not remove any runtime blocker above.

## Expansion issues which must not block this isolated readiness decision

For a no-expansion/no-module game, none of the following exists: Richese cache cards/No-Fields, CHOAM Worthless powers/Auditor, Ix forces/mobile stronghold/Poison Tooth/Sandtrout, Tleilaxu Face Dancers/gholas, Ecaz ambassadors/Duke, Moritani terror, or leader skills/stronghold cards/homeworlds/Nexus cards/discoveries/tech tokens. Their missing behavior remains required by the overall goal, but does not itself prevent a genuinely completed six-base-faction Advanced mode from being enabled later.

In particular, Stone/Poison Tooth choice ordering, mixed No-Field battles, Residual Poison secret-captive disclosure, Ornithopter-card/Hajr/advisor composition, and foreign-ghola acquisition are **not** base Advanced blockers. Base city ornithopters, base Ghola card and ordinary Harkonnen capture are separate, relevant mechanisms. Do not hold an otherwise completed base mode for unrelated faction art or copy the expansion guards into it.
