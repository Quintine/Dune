# Remaining Ecaz Ambassador effects: next gameplay slice

Independent source/runtime review, 7 September 2026. **Recommend implementing the reusable Ecaz Ambassador’s direct acquisition of Duke Vidal for Ecaz.** This is a real currently unavailable entry effect with an existing custody/battle lifecycle. Keep the separate alliance proposal, ally assignment and loan branches visibly unfinished. This recommendation does not enable full Ecaz starts or settle Occupy.

`game/engine.ts:6220` enables Atreides, Harkonnen, Emperor, CHOAM, Ixian and BG copying. `ambassadorEffectBlock` disables the others. `openTerritoryEntry` at approximately6292 owns the real interruption and still rejects competing arrival reactions. ## Concrete direct-acquisition contract

The following is a proposed software contract, with existing engine rules/gates preserved:

1. Retain the actual qualifying entry producer and its exclusions. At an Ecaz-token offer, expose a distinct **Acquire Duke Vidal for Ecaz** action and the ordinary leave-in-place action. Do not relabel the existing generic trigger as though it implemented the token’s entire choice set. Proposed command: `{type:'decision',event,trigger:true,beneficiary:ownerId,choice:'duke'}`. Explicit choice avoids future alliance/loan dispatch ambiguity; the field name is an implementation proposal.
2. Prevalidate the current physical token, source event, Ecaz actor/beneficiary, and canonical shared Duke before token commitment. Use `acquireDuke(g.dukeVidal, owner.id, g.turn, 'ecaz')` to obtain the next custody record, then commit that record with the token in one accepted action. `initializeStartingForces` near engine3351 already creates the shared disc for Ecaz/Moritani, and the Moritani offer also initializes an absent legacy disc. Follow those existing initialization conventions; never replace a present disc or erase its death history.
3. The shared helper at `game/duke-vidal.ts:47` already supports source `ecaz`. It preserves the exact leader and rejects the printed unavailable custody. It allocates no event or random value. A current Moritani-controlled eligible disc is the same physical disc to transfer, not another leader to manufacture. Preserve `usedAt` and existing battle eligibility: transfer is not permission to use a previously committed leader twice.
4. `triggerAmbassador` at `game/ecaz-ambassadors.ts:302` already returns the Ecaz token to supply rather than marking it used. Preserve that result and the untouched five-token cohort. Correct the generic engine log, which currently says every non-BG triggered token is set aside. An Ecaz trigger must not cause a new random draw merely because it is reusable.
5. With no further acquisition choice, finish in the same action. Call the existing Ambassador suffix once. Preserve entrant `active`, movement/shipment counts, paid costs, pending parent and turn/phase. A worm-origin offer resumes exactly its existing worm continuation. Do not add a new generic Ambassador Karama response: the existing placement cancellation contract remains separate.
6. Preserve actual Duke lifecycle consumers. `controlledLeaders` near engine7847 supplies the controlled disc; battle resolution near9315 consumes its custody after use; `expireDuke` at `game/duke-vidal.ts:86` leaves source `ecaz` intact across turns. Existing Advanced-Harkonnen/exotic-custody gates still apply, because those games currently exclude Duke from usable leaders. Acquiring an unusable disc must not be presented as complete support for that combination.

The same-owner already-controlled case is an inherited no-op trigger question. For this slice, leave that option explicitly unavailable as unfinished rather than inventing a printed rule about recycling the token. Similarly, keep ally assignment/alliance/loan controls marked unfinished. Ecaz self-acquisition remains usable when Ecaz already has an ally; the future loan question is not a reason to require Ecaz to be unallied merely to acquire for itself.

## UI, bots and privacy

`components/ecaz-entry.tsx` currently has only offer/copy/cards branches and a hardcoded coverage sentence. Add the explicitly named self-acquisition action, its current eligibility reason, and the existing Duke inspector. Keep alliance/loan status separate from the enabled action. No confirmation-only intermediate decision is needed after the player chose acquisition. Update `game/ambassador-reference.ts` and the special-leader implementation metadata to distinguish implemented self-acquisition from remaining printed alternatives.

`viewGame().ambassadorEntry` near15563 currently returns owner-only beneficiary eligibility. Extend it with the bounded current choice descriptor needed by the UI and bots. Derive this from public disc/custody facts in supported configurations; do not expose hidden capture details through a new blocked-reason string. No opponent hand, spice, traitor or hidden leader data is needed. Broadening a public eligibility window from hidden data would be a separate privacy change.

`game/bots.ts:1373` currently chooses the first available generic beneficiary. Add an explicit branch emitting the same `choice:'duke'` action for the owner when offered; preserve leave-in-place fallback for unavailable branches. All four profiles must use the projected descriptor. The new effect should not fall into the current generic card-selection tail. BG’s existing copy pool excludes the reusable Ecaz token; do not add a synthetic BG→Ecaz copy while enabling this handler.

## Evidence required for the production slice

- Genuine movement/shipment entry→self-acquisition, including Ecaz with an existing ally, Moritani as entrant, and leaving the token in place. Show same physical Duke ID/death history, exact source/controller, returned token, unchanged cohort and unchanged ordinary action counters.
- Availability cases: Tanks, captured/ghola custody, existing unsupported Duke table, and the explicitly unfinished same-owner/ally-choice cases. No unusable enabled action should consume the token.
- Actual subsequent battle selection/use/death and surviving unused Ecaz control across a turn; Moritani’s later qualifying acquisition still takes the same disc. Never append Duke to a native roster or traitor deck.
- Genuine worm interruption and final suffix once, JSON reload, concurrent duplicate accepted command through room CAS, no duplicate acquire/token/cycle change, all four bot profiles, and non-owner projection parity under private-hand perturbation.
- Browser check with the existing portrait/inspector, keyboard action labels, disabled explanations and truthful coverage copy. Preserve full Ecaz-start and competing-arrival gates.
